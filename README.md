# DialogSpyBot

Telegram-бот на **aiogram 3.x**, который ведёт журнал сообщений: сохраняет
всё входящее в SQLite, отслеживает правки (хранит старую и новую версию),
позволяет помечать удалённые сообщения и искать по истории.

## Возможности

- Сохранение каждого входящего сообщения: `chat_id`, `user_id`, `username`,
  текст, дата/время, `message_id`.
- Отслеживание редактирования сообщений с полной историей версий.
- **Мгновенные уведомления администраторам**: как только сообщение
  изменено — бот сам присылает «было → стало», при удалении — исходный текст.
- Пометка сообщений как удалённых.
- Команды `/history`, `/deleted`, поиск по тексту и по пользователю.
- Доступ к командам — только для администраторов из `ADMIN_IDS`.
- Асинхронная архитектура (SQLAlchemy 2.0 async + aiosqlite).
- Автоматическое создание таблиц при старте, логирование, конфиг через `.env`.

## Структура

```
bot.py            — запуск бота (Bot API)
config/           — настройки из .env (pydantic-settings)
models/           — ORM-модели (Message, MessageEdit)
database/         — движок, фабрика сессий, CRUD
services/         — бизнес-логика, форматирование, уведомления
handlers/         — роутеры команд и перехвата сообщений
userbot/          — Telethon-процесс: АВТОдетект удалений и правок
```

## Запуск

### Docker (рекомендуется)

```bash
cp .env.example .env       # впишите BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

### Локально

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env       # впишите BOT_TOKEN и ADMIN_IDS
python bot.py
```

## Команды

| Команда | Описание |
|---|---|
| `/history [N]` | последние N сообщений текущего чата |
| `/history_all [N]` | последние N сообщений по всем чатам |
| `/deleted [N]` | удалённые сообщения |
| `/search <текст>` | поиск по подстроке в тексте |
| `/user <@username\|id>` | сообщения конкретного пользователя |
| `/info <message_id>` | карточка сообщения с историей правок |
| `/markdeleted <message_id>` | пометить сообщение удалённым (или ответом на него) |

## Мгновенные уведомления

- **Правка** ловится автоматически: бот сразу рассылает всем `ADMIN_IDS`
  сообщение «Было → Стало».
- **Удаление**: при работающем userbot (см. ниже) — мгновенно и автоматически;
  без него — после ручной пометки `/markdeleted`.

## Автоматический детект удалений (userbot)

Telegram **Bot API не присылает событий об удалении** сообщений — обычный бот
узнать об этом не может в принципе. Это умеет только клиент MTProto, работающий
**от имени аккаунта**. Поэтому в проект добавлен необязательный userbot на
Telethon: он в реальном времени ловит удаления (и правки) во всех диалогах
аккаунта, помечает их в той же БД и присылает админам исходный текст —
отправку делает сам бот (вашим `BOT_TOKEN`).

### Настройка

1. Получите `api_id` и `api_hash` на https://my.telegram.org → *API development tools*,
   впишите их (и при желании `USERBOT_SESSION`) в `.env`.
2. Однократно войдите в аккаунт (создаст файл сессии в `data/`):
   ```bash
   # локально
   python -m userbot.login
   # или в Docker (интерактивно)
   docker compose run --rm userbot python -m userbot.login
   ```
   Telethon спросит номер телефона, код из Telegram и пароль 2FA (если включён).
3. Запустите всё:
   ```bash
   docker compose up -d --build      # поднимет и bot, и userbot
   ```

> ⚠️ **Важно.** Userbot работает от имени вашего аккаунта — это «серая зона»
> по правилам Telegram. Используйте только для своих чатов и на свой риск.
>
> Если один и тот же чат виден и боту, и userbot, по правке может прийти
> два уведомления (это безвредно). Чтобы избежать — добавляйте бот только в
> те чаты, где нет вашего аккаунта, либо полагайтесь на один источник.

## Сбор сообщений в группах

Чтобы бот видел все сообщения группы (а не только команды), отключите
**Group Privacy** у бота через @BotFather (`/setprivacy` → `Disable`) и
добавьте бота в чат. Для каналов добавьте его администратором.
